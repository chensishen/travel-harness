修复原因与处理：

- 原地理编码只查询完整名称一次且直接取首项。现在核对城市和名称、排除车站及同名商户，支持有来源的别名与 L1/L2 门牌地址。道路分段只在同名且边界相连时选择实际地图代表点。1933 老场坊通过官方来源中的沙泾路门牌定位到建筑，排除了另一门牌的咖啡馆结果；没有编造坐标。
- 原审阅没有区分事实与编辑建议，整篇重写又可能引入新问题。现在用稳定段落编号定点修正，明确标记编辑建议；两轮后仍无依据的段落可以省略并留审计记录，随后重新审阅剩余全文。事实、引文、数字及敏感字段规则继续生效；文化主题不足五个仍阻止发布。
- 原项目只接 Commons，实际请求为 403。现使用配置中的 `magpie-image` MCP，动态发现并校验参数，同一会话提交一次、轮询原任务，已生成图片按主题缓存以供重试复用。首次生图实测暴露 Magpie 指向不存在的模型；用户重新配置后实际生图成功。
- 修复插画文件前缀未获下载接口允许而导致网页图片 404 的问题；补充章节插画预览和编辑建议标签。清除已解决的旧缺图警告，重新生成预览时移除旧页，避免显示上一次导出残页。

验证：47 项 pytest 通过（包含真实 Milvus 临时数据库集成）；Ruff、Python 编译、前端 TypeScript / Vite 构建通过。已通过真实 HTTP 下载检查 PPT / Word / JSON、检查 Office ZIP 完整性、核对图片标签及所有插画接口，预览页数与实际 PPT 页数一致；浏览器显示已完成及下载入口。已抽看真实导出的路线页和配图页，未逐页审查全部内容。

证据：`data/generation-repair-results.json`、任务目录内 `review-*.json`、`repairs-*.json`、`state.json`、`travel.pptx`、`travel.docx`、`deliverable.json`；浏览器截图 `data/qa/completed-downloads.png`。这些本机产物包含真实模型结果，不是合成测试样本。

仍有边界：AI 插画不是景点实拍；门票、开放时间、预约等许多字段仍未核实，不能把生成成功当作事实准确率验收。坐标未完成第二来源交叉核验，交通仍为估算；全部营业窗口、整体图文相关率和八分钟性能目标尚未验收。当前按全文拆页的 PPT 较长，不是精简汇报版。

## 本次修复及验证

1. 本机 DNS 使用 `198.18.0.0/15` Fake-IP。增加默认关闭、仅本机显式开启的兼容配置；字面保留 IP、私网与本机地址仍拒绝。
2. 三日规划曾输出 36 个候选景点。增加按天数生成的 Schema 上限，实测重新规划为 12 个。
3. MCP TLS 连接偶发失败。只对连接类错误有限重试，保留参数/内容错误；单页 MCP 抓取失败可走既有 HTTP 通路。
4. 展开聚合异常的安全诊断，避免只看到 `ExceptionGroup`。
5. 敏感字段错误引用 L3 时明确标为未核实；写作与审阅提示同步约束。保留未核实警告，不冒充有效来源。
6. 抽取要求逐字复制单一原文片段；保存候选事实便于回查。引文检查规范中文排版空白，继续拒绝改动数字、字词或空白引文。
