# 第一轮提速落地与验证

日期：2026-10-30。对应 performance-optimization-plan.md 的第一批中可独立验证的改动，保留原有模型、检索数量与候选上限、质量门槛和 Office 转换检查。

## 已启用

- 搜索与结果提取两路并发，合并、编号、入库仍按原问题顺序执行。知识库查询保留前一问题入库后的可见性。
- 同一问题的候选网页并行读取，最多三个网站同时抓取；同一网站串行且完成后至少间隔一秒。robots、公开地址检查、重定向限制及正文处理保持原逻辑。
- 正文和查询按原文精确缓存向量。缓存键包含接口地址、模型、编码和输入正文；正文或模型改变即重新计算，知识库写入及维度检查仍执行。混合命中只计算缺失输入，恢复原输入顺序。
- 模型请求复用 HTTP 连接，最多两路请求；服务结束时关闭连接。
- PRD 1.1 的装饰封面生成与照片核验重叠执行，照片选取、授权与视觉核验保持原顺序，去重集合按任务重置。
- 任务记录新增外部操作耗时、模型额度等待、缓存命中和错误类别；不记录请求正文、密钥和带凭据地址。操作计时不混入已完成阶段耗时样本。
- 同阶段失败时取消并收拢其他并发操作，完成前仍等待入库与产物检查。整任务并发仍为一，未启用多个城市同时生成。

未启用：逐景点核验函数并发、MCP 工具选择缓存、正文/路线/配图跨阶段改写。这些涉及共享来源、规则失效或 document 合并，需分别验收，不能直接把现有函数放入并发执行器。

## 实测

固定响应回放：新执行器并发额度 1 与 2 的三组成对对照，保留相同检索范围和固定网络延迟。中位耗时 0.828 秒与 0.589 秒，减少 28.9%；每组来源、编号、正文和调用数量一致。这是受控环节对照，不能等同于真实城市全流程加速。

真实 Qwen 向量服务：杭州两条已采集公开来源各取前 4000 字符，首次请求约 0.783 秒；相同输入缓存命中约 0.004 秒，两条 4096 维向量完全一致。该试验仅衡量向量复用。

真实修改任务 de014eb0-2136-4475-a20d-59d4f0f1bbbe：更新后服务完成模型分析、文档排版和质量检查，总计 10.4 秒，PPT / Word 下载均为 HTTP 200；忽略任务目录后结构化内容与原稿一致。此任务不重跑资料检索，不作为全新城市提速证据。

完整测试 81 项通过，含真实 Milvus；之后补充同站访问间隔用例，提速专项 8 项全部通过。Ruff 通过。覆盖并发限制、稳定编号、查询可见性、取消、同站访问间隔、向量缓存失效及顺序、连接关闭和计时隔离。

原始记录：data/qa/performance-benchmark.json、data/qa/performance-live-job.json。可用 `.venv/bin/python scripts/benchmark_performance.py --live` 重跑固定响应对照与真实向量探测；该参数会调用已配置的向量服务。

尚未进行当前版本冷缓存全新城市成对回归，不能承诺端到端降低 25%–40%。已应用的改动旨在消除可验证的等待与重复计算。
